## How it works

1. `DreadmoorVR_P` mounts from `~mods` (IoStore, chunk 1).
2. Lua (`m1_probe.lua`) sends the custom event `dreadmoorvr_request_class`.
3. The plugin calls `KismetSystemLibrary` `MakeSoftObjectPath` → `Conv_SoftObjPathToSoftObjRef` →
   `LoadAsset_Blocking` through `process_event`. The parameter blocks are laid out from
   reflection.
4. The plugin replies with `dreadmoorvr_class_loaded`.
5. Lua spawns the actor with `BeginDeferredActorSpawnFromClass` + `FinishSpawningActor`, then
   moves it 150 cm ahead with `K2_TeleportTo`.

## Why this route

UEVR's Lua returns `nil` for soft-reference conversions, so it can't load pak classes itself.
Native code can, because it lays out the parameter memory directly. This is the
"C++ plugin" fallback the M1 gate anticipated.
