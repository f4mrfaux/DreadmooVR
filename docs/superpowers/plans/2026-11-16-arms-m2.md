# Arms (Bob's M2, spec M3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Editor work goes through the EngineWire MCP. Bulky reads go to the local model (local-delegate).

> **Status (2026-11-17): M2 implementation and smoke pass completed.** The arm actor, AnimBP
> targets, hide/restore flow, and hand-item attachment are implemented. Current shoulder and
> camera tuning evidence is in `docs/research/2026-11-17-arms-shoulder-review.md`; held-item
> findings are in `docs/research/2026-11-17-held-items.md`. This plan is retained as the original
> implementation checklist, not a list of remaining work.

**Goal:** On foot, Bob sees arms in the game's character style following both Frame
controllers, with natural elbows. The game's own arms and head are hidden. (Spec M3 "done
when", minus fingers and D12 shoulder-follow, which are the next pass.)

**Architecture** (spec §6):
- `BP_VRArms` (actor) has a skeletal mesh component using the stand-in player mesh, with
  `ABP_VRArms` (Two-Bone IK per arm plus a wrist rotation) on the stand-in skeleton. It also
  has two hand-target components that UEVR drives to the controllers.
- The plugin loads the class (the M1 route), and Lua spawns it, attaches it, registers the
  targets and hides the game body's arms and head.

**Spec:** `docs/superpowers/specs/2026-11-15-dreadmoor-vr-gestures-design.md` §5 "Arms,
everywhere", §6 "The pak", M3.

## Global Constraints

- Stand-ins are **never cooked**. The pak file list must contain only `/Game/DreadmoorVR/*`
  (`list_container.py` fails on anything else).
- Every engine call is validated against the UE 5.6 headers and recorded in
  `docs/research/validated-engine-calls.md` before use.
- The nightly 01143 renderer and the 15:29 benchmark config stay untouched. Rollback:
  `deploy.ps1 -RemovePlugin` plus removing `m2_arms.lua`.

## Rulings

- **The stand-in comes from UE 5.6's own mannequin, not an FModel export.**
  - Why: the game's `SK_DreadMoreSkeleton` has every UE5 Manny core bone (`clavicle`,
    `upperarm`, `lowerarm`, `hand`, the fingers, `ik_hand_*`), read from its package name
    table. `SK_Mannequin` and `SKM_Manny_Simple` ship with UE 5.6, so no download is needed.
  - Cost if wrong: bone binding fails at runtime. Fall back to the spec's FModel export.
- **The player mesh path has a capital "New"**:
  `/Game/Dreadmoor/Animations/Characters/New/dm_demo_NewProtagonist`, using
  `/Game/3rdParty/TFPMovement/Demo/Character/Mannequins/Meshes/SK_DreadMoreSkeleton`
  (read from the game's package imports).

## Review Focus

1. **The game's real skeleton lacks a bone the AnimBP names:** the arms stay in the reference
   pose rather than crashing. Only core Manny bones are used.
2. **Pawn switch** (fishing, bench, boat): the arms are hidden and re-attached, never left
   floating. This pass is walking only, and other pawns hide the arms.
3. **A controller loses tracking:** UEVR holds the last pose. Accept that for this pass and
   log it via the plugin's pose validity.
4. **A stand-in sneaks into the cook:** `list_container.py` fails the build.
5. **A script reset spawns a second arms actor:** destroy the old one first.
